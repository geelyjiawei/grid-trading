# 网格机器人详情展示

本次仅调整 Vue 展示层，参考 Binance 交易机器人截图的信息层次，保留控制台现有的绿白与深色主题。没有新增下单请求、轮询定时器或交易所 API 调用，也没有修改 Rust 交易状态机。

## 使用入口

主页继续展示策略状态、盈亏和网格参数。**交易所权威数据**区域只保留四个分类入口，点击任一分类直接从右侧打开对应明细，不必先进入策略盈亏或网格参数：

- **持仓**：方向、杠杆、数量、开仓均价、标记价、未实现盈亏、强平价。
- **挂单**：按精确价格排序，可筛选买卖方向，每页 10 条；展开后查看原始订单号、已成交数量和时间。
- **成交**：逐笔成交与 Maker/Taker 信息，可展开查看费用、盈亏及原始成交编号。
- **历史**：仅展示当前交易所、当前交易对的历史策略记录，不伪造网格配对明细。

桌面抽屉宽度最多 920px，背景变暗且不可交互，抽屉独立滚动；手机端占满屏幕。支持右上角关闭、Esc、点击外部关闭，关闭后恢复页面滚动和入口焦点。使用原生模态 `dialog`，正常数据刷新不会自动关闭抽屉；交易所、交易对或 API 配置可用状态改变时关闭旧详情。抽屉内不提供启动或停止策略操作。

## 数据边界

- 当前挂单与成交接口属于账户在该交易对上的记录，可能包含手动订单，不将其直接标记为本轮网格订单。
- `reduce_only` 只表示是否只减仓。`false` 不等于一定是开仓单，不能据此判断订单归属。
- 保留交易所原始十进制数据；部分成交显示剩余数量与原始数量，不强制四舍五入成整数。
- 成交条数指当前接口已加载的成交笔数，一张订单可以分多笔成交，不能作为订单总数或网格配对数。
- Maker/Taker 分类仅以接口提供的 `is_maker` 为依据，缺失时显示类型未知。单笔已实现盈亏不是网格配对净利润。
- 历史接口返回账户范围的策略记录，展示层按当前交易所和交易对筛选。缺少身份字段的历史记录不混入列表。
- 实时读取失败时保留上次成功快照并明确提示，数量显示未知，不显示为 0。
- 页签、筛选、分页和展开均为本地展示操作，不触发交易所请求；“刷新明细”复用现有刷新入口。

## 本地验证

在 `vue-frontend` 运行：

```powershell
npm test
npm run build
```

可另开终端运行只读模拟接口与开发前端：

```powershell
node test-support/bot-preview-api.cjs
```

```powershell
npm run dev
```

模拟接口只监听 `127.0.0.1:8000`，使用人工构造的数据，不读取密钥、不连接交易所、拒绝所有写入请求。前端使用 `http://127.0.0.1:5173`，点击模拟 PONSUSDC 策略进行验证。此预览不代表生产账户数据。

已检查桌面与 375px 手机端的深浅色正常状态；自动化测试覆盖精确排序、分页、筛选重置、部分成交、跨交易所历史隔离、快照失败和停止确认。

## 发布边界

本地构建不等于服务器部署。本次界面改动无数据库迁移；发布应走现有预构建镜像流程，不在生产服务器运行 Rust 编译。不要为了预览界面重启仍有运行中策略的交易容器。
